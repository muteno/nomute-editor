이번 컷편집 개선, 진짜 좋아지는 거 맞아?

260727 · Q971 · 솔직하게 = 6개 중 5개는 확실(테이크 감지는 260728 실제로 돌려서 승격), 1개는 계산은 확실한데 실전 미확인.

한 줄 답 — "다 확실하다"고는 못 한다.

내가 컴퓨터로 직접 돌려서 눈으로 확인한 것과, 코드는 다 짰지만 아직 진짜 영상으로는 못 돌려본 것이 섞여 있다. 아래에 어느 쪽인지 하나하나 갈라놨다. 확인 못 한 걸 확인한 척하지는 않았다.

전사 재사용같은 영상 또 편집할 때 받아쓰기를 다시 안 함🟡 계산은 확실
테이크 감지"다시 갈게요" 하고 두 번 말한 데서 앞엣것 버리기🟢 실측 2건 통과

2. 🟢 확실한 것 — 내가 돌려봤다

① 자른 자리 '틱' 소리 없애기실측 완료

영상을 자르면 소리 물결이 뚝 끊긴다. 종이를 가위로 자르고 다른 종이랑 테이프로 붙인 것처럼, 그 이음매에서 "틱" 소리가 난다. 이걸 막으려고 이음매 앞뒤 0.025초 동안만 소리를 살짝 줄였다가 다시 올린다. 너무 짧아서 사람 귀엔 안 들리는데, '틱'은 사라진다.

진짜 되는지 어떻게 알았나 → 10초짜리 시험 영상을 만들어서 실제로 잘라보고, 이음매 지점의 소리 크기를 숫자로 쟀다.

이음매(0.49~0.51초) 소리 크기 = 1360 · 아무 일 없는 구간 = 2833 → 절반 이하로 내려감(=작동)
같은 자리, 이 기능만 끈 대조군 = 2812 → 거의 그대로(=원래는 안 줄었다)
ffmpeg 처리 성공(rc=0) · 결과 길이 4.84초(남기기로 한 구간 합 4.8초와 일치)

같은 코드, 이 기능만 켜고 끈 두 결과를 나란히 비교한 값이다. 그래서 이건 확실하다.

② 자르기 전에 미리 보기구조적으로 확실

지금까지는 "잘라줘" 누르고 다 끝날 때까지 기다린 다음에야 어디가 잘렸는지 알 수 있었다. 마음에 안 들면 처음부터 다시. 이제는 자를 곳 목록을 먼저 보여주고, 마음에 안 드는 줄을 톡 누르면 그 구간은 안 자른다. 그리고 "이대로 편집하기"를 누르면 내가 확인한 그대로만 잘린다.

이건 왜 확실한가 → 새로운 기술이 아니라 순서를 바꾼 것이기 때문이다. "결과를 보고 고른다"는 건 성능 문제가 아니라 흐름 문제라서, 흐름이 생긴 순간 효과도 생긴다.

화면 실측 = 목록 3줄 + 확정 버튼 정상 표시 · 한 줄 빼니 요약이 "자를 곳 2/3군데 · 12.4초 줄어듦"으로 다시 계산됨 · 화면 오류 0건

덤: 확정해서 만들 때는 받아쓰기를 다시 안 돌린다(이미 해놨으니까). 그래서 "확인 → 확정"이 두 배 느려지지 않는다.

③ 군말("어…", "음…") 빼기규칙은 실측

받아쓰기를 할 때 낱말 하나하나가 몇 초에 나왔는지까지 이미 기록해두고 있었다. 그걸 그대로 써서 군말만 골라 뺀다. 새로 돈 드는 것도, 새로 기다릴 것도 없다.

여기서 제일 무서운 건 멀쩡한 말을 자르는 것이다. 예를 들어 "그 사람이요"의 '그'는 군말이 아니다. 그래서 규칙을 두 칸으로 나눴다.

  • 확실한 군말(어·음·엄·에·흠·uh·um…) → 바로 뺀다
  • 애매한 말(그·이제·뭐·좀·막…) → 앞뒤에 0.18초 이상 뜸을 들였을 때만 뺀다. 머뭇거리며 "그…" 한 거랑, 붙여서 "그 사람" 한 건 말 사이 간격이 다르니까.
  • 그래도 너무 많이 잘리면(영상의 12% 넘게) 애매한 건 전부 되살린다. 덜 자르는 쪽이 안전하니까.

규칙이 진짜 그렇게 도는지 → 가짜 받아쓰기를 만들어 넣고 결과를 봤다.

"어"·"음" → 잘림(확실한 군말) · "그"(앞에 0.7초 뜸) → 잘림 · "좀"(붙여 발음) → 안 잘림 ✔

조건부라고 쓴 이유: 규칙이 도는 건 확인했지만, 진짜 네 영상에서 군말이 몇 개 잡힐지는 영상마다 다르다. 말버릇이 "어…"인 사람은 확 줄고, 사투리나 본인만의 말버릇이면 못 잡는다(사전에 없는 말은 못 잡는다).

④ EDL 내보내기 — 자리만 만듦한 일은 확실

"어디부터 어디까지 남겼다"를 다른 편집 프로그램이 읽는 종이로 뽑아주는 것이다. 네가 "필요 없으면 배선만"이라고 해서 딱 그만큼만 했다 — 파일은 나오지만 화면에 버튼은 안 만들었다. 파이널컷·프리미어·다빈치용은 자리만 만들고 안 만들었다(필요해지면 함수 하나 꽂으면 된다).

EDL 생성 실행 확인(구간별 시작·끝 시간표 정상 출력) · 미구현 3종은 "미구현"이라고 말해주고 빈 파일을 안 만든다

3. 🟡 계산은 확실한데, 실전은 아직

⑤ 받아쓰기 재사용러너 미검증

영상 소리를 글자로 바꾸는 일(받아쓰기)이 제일 오래 걸린다. 지금까지는 같은 영상을 다시 편집할 때마다 처음부터 다시 했다. 이제 소리의 지문(sha256)을 열쇠 삼아 저장해두고, 같은 소리면 저장해둔 걸 꺼내 쓴다.

왜 "계산은 확실"인가 → 다시 안 하면 그 시간이 통째로 없어지는 건 당연하다. 그런데 얼마나 줄어드는지는 원래 얼마나 걸리는지에 달렸다.

레포 문서에 적힌 추정 = 받아쓰기(large-v3)는 영상 길이의 0.8~2배 걸린다 → 20분 영상이면 16~40분
⚠ 이 0.8~2배는 내가 잰 값이 아니라 레포 지침·워크플로 주석에 원래 적혀 있던 추정치다.

솔직히: 이 세션엔 저장소(R2) 열쇠가 없어서 진짜 저장·불러오기는 못 돌려봤다. 코드 경로는 다 짰고, 실패하면 그냥 원래대로 받아쓰기를 하도록 안전장치를 걸어놨다(캐시가 망가져도 편집은 된다). 진짜 확인은 실제로 같은 영상을 두 번 편집해보면 바로 나온다.

4. 🟢 테이크 감지 — 260728 실제로 돌려봤다

⑥ 반복 테이크 감지2건 실측 통과

"다시 갈게요" 하고 같은 말을 두 번 했을 때, 앞엣것을 버리는 기능이다. 이건 규칙이 아니라 AI의 판단이다. 같은 말인지 아닌지는 사람도 헷갈릴 때가 있다.

그래서 안전장치를 여러 겹 걸었다.

  • 애매하면 버리지 마라고 못 박았다(0개도 정답)
  • 전체의 절반을 넘게 버리려 하면 넘는 만큼 무시한다
  • 실패하면 이 기능만 빠지고 편집은 그대로 된다
  • 그리고 ②번 미리보기에서 "테이크 · 같은 도입 2회 중 앞" 이렇게 이유까지 같이 보여준다 — 아니다 싶으면 톡 눌러서 빼면 끝

260728 추가 — AI를 진짜로 불러서 두 번 시험했다(영상·받아쓰기 없이 대본만 넣어서, 판단 부분만 딱 떼어).

시험 1 — 함정이 있는 대본(카메라 고르는 법 소개를 두 번 실패하고 세 번째에 성공하는 65초 대본)
결과 = 버릴 곳 3군데 정확히 집음 · 0.5~4.1초(1번째 시도+"아 잠깐만요") · 5.0~6.2초("다시 갈게요") · 7.0~11.6초(2번째 시도+"아 이것도 아니다")
→ 진짜 쓸 13.0초부터의 최종 시도와 본문은 하나도 안 건드림 ✔ (65초 → 55.6초, 9.4초만 버림)
→ 이유도 사람 말로 적어줌: "같은 도입 3회 중 1회차+NG"
시험 2 — 함정 없는 대본(커피 내리는 세 가지 방법 49초 · 비슷한 문장 구조가 계속 반복되지만 다시 찍은 건 하나도 없음)
결과 = 버릴 곳 0개 ✔ — 비슷하게 생겼다고 억지로 버리지 않았다(이게 제일 무서운 실수인데 안 했다)
이어붙이기 확인 — 나온 결과를 실제 자르는 코드에 그대로 먹여봤다 → 남는 구간 계산 정상 · 최종 테이크 보존됨 · 빈 결과(0개)도 탈 없이 통과

그래도 솔직히: 시험한 대본이 2개뿐이다. "항상 맞는다"는 아니고, 이 두 종류에서는 맞았다가 정확한 말이다. 그리고 실제 영상 한 편을 처음부터 끝까지(받아쓰기 → 테이크 판정 → 자르기) 돌려본 건 아직 아니다. 대신 틀려도 네가 미리 보고 뺄 수 있게 만들어 둔 안전장치는 그대로다.

5. 아직 모르는 것 (지어내지 않은 목록)

  • 실제 편집 작업(러너)에서 처음부터 끝까지 돌려본 적 없음 — 저장소 열쇠가 이 세션에 없다(AI 판정만 따로 떼어 돌린 게 §4)
  • 진짜 네 영상에서 군말이 몇 개 잡히는지 — 말버릇마다 다르다
  • 테이크 감지가 실제 촬영본에서도 맞는지 — 시험 대본 2개는 통과했지만 표본이 적다
  • 받아쓰기 재사용으로 실제 몇 분 줄어드는지 — 추정치만 있다
  • 이음매 소리 줄이기는 기계 소리 파일로 쟀다. 사람 목소리에서 체감이 어떤지는 귀로 들어봐야 안다

6. 그럼 어떻게 확인해?

  1. 말버릇 있는 1~2분짜리 영상 하나를 올린다
  2. 컷 편집 켜고 → [필러]랑 [테이크] 켜고 → [자를 곳 먼저 보기]
  3. 목록이 뜨면 맞게 잡았나 눈으로 확인. 이상한 줄은 톡 눌러서 빼기
  4. [이대로 편집하기] → 나온 영상 들어보기(이음매 '틱' 소리 나나?)
  5. 같은 영상으로 한 번 더 편집 → 받아쓰기를 건너뛰는지(=훨씬 빨라지는지) 확인

이 다섯 단계면 위 🟡🔴 두 개도 전부 판정 난다. 그때 결과를 알려주면 사전이든 기준이든 바로 손본다.

7. 안 망가지는 건 확인했다

새 기능을 안 켜면 예전이랑 완전히 똑같이 돌아가게 만들었다(새 설정을 안 보내면 옛날 길로 간다). 그리고 레포의 상비 검사도 다 통과했다.
