  1. 3면 동기 게이트 — 축을 sb로 옮기면 viewer/k.html·functions/api/k.js·apps/k/01_모델프로필_영상엔진.md 3면을 강제하는 check_refs.check_k_models()가 sb 쪽에도 걸려야 한다(한쪽만 고치면 커밋 rc=1). 이 시안은 게이트를 통과하지 않는 정적 사본.
    2. 
        
  2. k 탭을 지우면 잃는 것 — 리롤(축 지정 재설계)·장면 분막(구간별 초·내용)·레퍼런스 다장(≤7장)·대사 리터럴 칸·모델 Veo 3.1. 위 「프롬프팅 전량」 프리셋은 이걸 전부 켜서 개수를 보여주지만, 배치까지 확정한 건 아니다(⚠배치 = 사후 확인 대상).
    3. 
        
  3. Seedance 자동생성 블로커 — 대화 세션엔 힉스필드 MCP가 붙어 있어 지금도 돌지만, 웹앱 경로(GitHub Actions 러너 claude -p)의 --mcp-config 인증은 미실측 = 설계확정본 §2 M2 블로커. 잔액 실측 = 10크레딧 · free(15s·720p·std 1편 = 68cr) → 충전 없이는 자동 레인 자체가 못 돈다.
    4. 
        
  4. 비용 줄은 보수 추정 — 720p·std 4.5cr/s + 운영자 규칙(≤8s=8s가·9s=10s가·10~15s 선형·애매하면 위로)로 계산. 확정 견적 = 생성 직전 실시간 get_cost가 정본.
    5. 
        
  5. 「촬영」과 「비디오 모델」은 중복 축 — 콘티 촬영(Kling/Seedance) = 레인 분기 · k 비디오 모델(Kling/Veo/Seedance) = 방언 분기로, 합치면 같은 걸 두 번 고르게 된다. 이 시안은 두 축을 종속 동기(하나 고르면 다른 쪽 따라옴)로 묶었다 — 라이브에선 축 하나로 합치는 게 정답이고, 그러면 Veo 3.1을 촬영 칩에 3번째로 올릴지 결정해야 한다(각주 2).
    6. 
        
  6. 화풍 레일 — k 탭의 표현1·2·네거티브는 가로 레일(끝선 페이드·화살표) 부품이다. 여기선 카드 안 가로 스크롤로만 재현했으니, 라이브 이관 때는 k의 railRow 부품을 그대로 들고 와야 한다(재설계 금지).
