## 0. 한 줄

지금 규범(§3 5요소)은 **"무엇을 넣을까"**를 잘 정의한다. 실제로 시안을 여러 번 만들어 보니 결정 품질을 좌우한 건 그게 아니라 **"운영자가 조작하는 동안 판단 대상이 눈에 남아 있는가"**와 **"보고 있는 게 실물인가 내 상상인가"** 두 가지였다. 그래서 아래 3개를 **필수 요소로 승격**하자고 제안한다.

## 1. 승격 제안 ①: 「미리보기 고정」 = 레이아웃 계약 (필수)

### 무엇
- **PC**: 좌 미리보기 `position:sticky` 고정 / 우 콘솔만 스크롤.
- **폰(세로형)**: 상단 미리보기 `position:sticky; top:0` 고정 / 아래 콘솔만 스크롤.
- 고정 영역은 `max-height`로 뷰포트를 넘지 않게 클램프(PC `calc(100dvh - --sp-4)` · 폰 `62dvh`).

### 왜 (실측 근거)
기존 §6 안티패턴에 **「콘솔 조작마다 미리보기가 최상단으로 튕김」**이 있다(260712). 이건 같은 병의 *증상 하나*였다. 근본은 **미리보기와 콘솔이 같은 스크롤 흐름에 있다**는 것 — 축이 15~20개로 늘어나면 콘솔이 길어져서, 아래쪽 축(폰 크기·배경·산출 유형)을 만질 때 미리보기가 화면 밖으로 나간다. 스크롤 보존을 아무리 잘 해도 **애초에 안 보이면 소용이 없다**.

오늘 코너 레일 시안이 정확히 그랬다: 축이 16개가 되자 `③-e 폰 크기`·`③-f 캡슐 라운드`를 조정하는 동안 미리보기가 안 보였다. sticky로 바꾸고 실측했다 — PC는 900px 스크롤 후에도 `stagewrap.top = 18` 불변, 폰은 700px 스크롤 후에도 `top = 0`.

### 규범 문구 제안
> ⑥ **미리보기 고정** — 미리보기는 콘솔과 **별도 스크롤 문맥**에 둔다. PC = 좌측 sticky, 폰 = 상단 sticky. 뷰포트를 넘지 않게 `max-height` 클램프. 검증 = 헤드리스에서 스크롤 후 미리보기 rect가 불변임을 실측.

## 2. 승격 제안 ②: 「실물 주입」 (필수 · 재현이 아니라 실물)

### 무엇
가능하면 **실제 산출물/실제 데이터**를 시안에 넣는다. 못 넣으면 근사임을 각주에 쓴다.
- 이미지·산출물 = **긴 변 480px·WebP·base64 임베드**(자기완결 유지). 7장에 74KB면 충분하다.
- 프리셋 칩으로 골라 미리보기에 즉시 적용.

### 왜
오늘 배경 축에서 드러났다. 미리보기 스테이지가 **순흑**이면 `backdrop-filter`가 시각적으로 **0**이다. 블러 8px이든 22px이든 화면이 똑같아서, 블러 축 슬라이더가 있어도 **판단 자체가 불가능**했다. CSS 그라데로 가짜 배경을 만들어 넣자 비로소 블러가 보였고, 실제 산출물 7종을 넣자 「이 배경에선 흰 글씨가 죽는다」 같은 **대비 판정**까지 가능해졌다.

즉 **"만질 수 있게"만으로는 부족하다 — 만진 결과가 시각적으로 드러나는 조건까지 갖춰야 한다.** 순흑 위 블러 슬라이더는 형식상 5요소를 충족하지만 실질은 죽은 축이다.

### 규범 문구 제안
> ⑦ **실물 주입** — 판정 축이 *배경·대비·블러·투명도*를 포함하면, 그 효과가 드러나는 실물(또는 무늬 있는 대체 배경)을 반드시 함께 넣는다. 단색 위에서 이 축들은 **죽은 축**이다. 실물은 축소 후 base64 임베드(외부 요청 0 유지) · 원본 화질 판정 불가는 각주에 명시.

## 3. 승격 제안 ③: 「전 조합 갤러리」 (조건부 필수)

### 무엇
변형 축이 2개 이상 곱해질 때(예: 유형 2 × 포맷 3), 세그로 하나씩 토글하는 대신 **전 조합을 한 화면에 동시 렌더**한다. 콘솔 축을 만지면 모든 칸이 같이 갱신된다.

### 왜
운영자가 「헤더형, 오버레이형 릴스 포스트 모두 넣었을 때 어떻게 되는지」를 **두 번 요청**했다. 첫 요청에 세그 토글로 답했는데, 그건 **한 번에 하나**만 보여준다 = 조합 간 비교가 기억에 의존한다. 갤러리로 바꾸자 즉시 드러난 것:

| 조합 | 레일이 놓이는 자리 |
|---|---|
| 릴스 9:16 | 스테이지 밖 **필러(빈 검정)** 위 — 블러 0, 콘텐츠에서 멂 |
| 포스트 4:5 | 스테이지 **경계에 걸침**(반은 필러·반은 그림) |
| 카드 1:1 | 온전히 **그림 위** — 블러 정상 |

이건 세그를 세 번 눌러서는 안 보인다. **한 화면에 놓여야 "포맷마다 다르게 깨진다"가 보인다.**

### 규범 문구 제안
> ⑧ **전 조합 갤러리** — 변형 축의 곱이 4 이상이면 전 조합 동시 렌더 패널을 붙인다. 콘솔 축 변경 시 전 칸 동반 갱신. (곱이 2~3이면 세그 토글로 갈음 가능)

## 4. 기존 규범에 덧붙일 것

### 4-1. 「정본 이탈」은 자동 판정으로 (§3-2′ 강화)
지금도 사다리 눈금 + ⚠ 실시간 + 복사 알림창이 있다. 여기에 **적용 범위 선택**을 추가하자. 오늘 실제로 문제가 됐다 — 코너 레일에서 `.trail-i` 폭을 22→39로 올린 건 "9:16"이 4자라 원 안에 안 들어가서 **불가피**했는데, 역제안 문구가 「.trail 쓰는 전 표면」이라고 적혀 있었다. 그대로 적용하면 SNS·채널 레일의 22px 픽토까지 알약이 된다.

> 역제안 블록은 **{전 표면 일괄 / 이 표면 한정 변주}** 를 운영자가 고르게 한다. 기본값 = **이 표면 한정**(무관한 표면 흔들림이 기본이 되면 안 된다).

### 4-2. 시안 자체의 클래스 이름 규칙 (신설)
오늘 실측 결함: 가로 레일 모디파이어를 `row`로 뒀더니 콘솔의 `.row{display:grid;grid-template-columns:1fr auto}`와 충돌해 레일이 2열 그리드로 접혔다(98×84 → 정상 208×28). 컴퓨티드 `flex-direction`은 `row`로 나와서 **원인이 안 보였다**.

> 시안 안에서 정본 컴포넌트를 재현할 때 **모디파이어는 컴포넌트 접두사를 붙인다**(`trail-row`, `trail-g`). 콘솔 유틸(`.row`·`.val`·`.seg`)과 이름이 겹치면 조용히 깨진다.

### 4-3. 「폭이 0으로 붕괴」 가드 (신설)
스테이지 자식을 전부 `absolute`로 바꾸자 shrink-to-fit 폭이 **0**이 되어 미리보기가 통째로 사라졌다. JS 에러도, 콘솔 경고도 없었다.

> 검증 체크에 **「미리보기 핵심 요소의 rect가 0이 아님」**을 넣는다. 스크린샷 눈으로만 보면 "까맣네" 하고 넘어간다.

### 4-4. 검증 항목 표준화 (§4 확장)
지금 §4는 {에러 0 · 실클릭 · 스크린샷}이다. 오늘 쓴 것들을 표준으로 올리자.

| 항목 | 판정 |
|---|---|
| `pageerror` · `console error` | 0 |
| 프리셋 전종 실클릭 | 단일 점등(이중 점등 = 비교 로직 버그) |
| 미리보기 실물 트리거 실클릭 | 상태 반영 확인(칩 → 팝 → 값) |
| 핵심 요소 rect | `> 0` (폭 붕괴 가드) |
| 스크롤 후 미리보기 rect | 불변(고정 계약) |
| 팝·오버레이 좌표 | 부모 박스 안쪽 클램프 |
| 겹침 판정 | 실사각 교차 면적(눈대중 금지) |

> ⚠ **프리셋 비교 함수의 함정**: `+'fluid'` = `NaN`, `NaN || 0` = `0` → 문자열 키가 늘 같아져 **전 프리셋이 동시 점등**한다(실측). 타입별로 비교하라.

## 5. 하지 말자고 제안하는 것

- **축을 50개 채우려고 죽은 축을 넣지 말 것.** §3-2′의 「평균 50개 안팎」은 *고도화 여지*를 주라는 뜻이지 개수 목표가 아니다. 단색 위 블러 슬라이더처럼 **효과가 안 보이는 축은 0개만도 못하다**(운영자가 만져보고 "차이가 없네" → 잘못된 결론).
- **정본 값을 슬라이더 기본값으로 안 쓰는 것.** 이미 §6에 있지만 한 번 더 — 기본값이 정본이어야 "안 만지면 그 컴포넌트 그대로"가 성립하고, 그래야 [선택값 복사]의 「계승/갱신」 표기가 진실이 된다.
- **한 시안에 결정 축을 3개 이상 섞는 것.** 오늘 하나의 파일이 {비율·레일 구성·폰 크기·배경·산출 유형}까지 커졌다. 운영자가 한 번에 하나씩 결정할 수 있게 **결정이 끝난 축은 다음 판에서 고정값으로 내려두는 게** 낫다(콘솔에서 빼거나 "확정분" 절로 격리).
