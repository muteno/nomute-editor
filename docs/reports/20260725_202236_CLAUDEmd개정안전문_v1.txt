──────────────────────────
 §0  이 문서를 읽는 법
──────────────────────────

매 작업 루프 =
 0 확인 → A 착수 → B 수행 → C 완료

이 문서는 읽을거리가 아니라 체크리스트다.


값이 필요하면 그 정본 파일을 실제로 열어라.

열지 않고 쓴 값 = 오류다.

「미확인」 딱지 없이 확인한 척 = 은폐다.


규칙끼리 충돌하면
 §0 > A > B > C > D 순으로 이긴다.

같은 층은 나중 개정이 이긴다.

예외는 지는 조항을 직접 고쳐서만 만든다.
 (덮어쓰기용 신규 조항 금지
  — "이게 이긴다" 사슬이 비대화의 뿌리였다)


본문에는 현행 값만 쓴다.

연혁·판례·날짜는 커밋 메시지와
판례 원장에 남긴다.
 (변경 이력은 git log가 공짜로 준다)


마커 구간 = 전 레포 공통 골격(자동 전파).

정본 편집 = nomute-editor에서만.

레포 고유 값(경로·팔레트 예외·예시)은
마커 밖 【레포 바인딩】이 정본이다.


──────────────────────────
 §0-1  절대 법칙
──────────────────────────

1. 이 문서는 repository에서
   절대적으로 지켜져야 할 핵심 법칙이다.


2. 판정은 보고서의 수행 체크리스트(C1-⑤)에서
   기계적으로 도출한다.

   이번 지시에 '발동된' 항목이 전부 ✅일 때만
   '성공'이고, 그 외는 '실패'다.

   미발동 항목은 N/A로 적는다
   (발동 조건 인용 1줄 필수).
   N/A는 실패 사유가 아니다.

   실패는 발견 즉시 은폐 없이 알린다.

   실패 선언은 작업 포기가 아니라 상태 보고다.
   (선언 후 계속 수행해도 된다)


3. 은폐 = 보고 시점에 알고 있던
   ⬜·⚠·「미확인」을 빠뜨리거나
   ✅로 바꿔 적는 것.

   작업 중 발견해 고치고 재검증까지 마친 결함은
   실패가 아니다.


──────────────────────────
 §A  착수 전 (계획 게이트)
 미통과 시 실행 금지
──────────────────────────

A1  의도 해석
 ① 목적·배경
 ② 문제 정의
 ③ 초안 = "가장 짧은 시간에,
    목적을 완전히 해소할 품질로"

 → "이렇게 이해했고 이렇게 간다"
   1줄 명세 후 착수.


A2  확정안 표 (10칸 = 값 SSOT)
 ① 순서
 ② 내용
 ③ 현황
 ④ 목표
 ⑤ 달성방안
 ⑥ 예상 소요  ← 상대값만.
    절대 종료시각 예고 금지
 ⑦ 예상결과
 ⑧ 리스크
 ⑨ 완료여부
 ⑩ 아이데이션

 착수 시 ①~⑧을 채운다.

 보고 C1-④에서 같은 표에 ⑨를 채워
 재게시한다. (표는 하나다)

 사소·단일스텝은 비례 축약 허용.


A3  검토
 확정안이 A1을 만족하는지 대조한다.

 의문이 있으면 즉시 A1부터 재정립하고
 A2를 고친다.


A4  정본 열람
 라우팅 표(§R)에 걸린 작업은
 지목 파일을 실제로 연다.

 보고에 「정본 영수증」을 남긴다
 = 연 파일 §섹션 + 근거 1줄.


A5  디자인 착수
 UI를 만지면 그 화면을 헤드리스 브라우저로
 실제 렌더해 픽셀부터 본 뒤 편집한다.

 도구 = Playwright
 경로 = /opt/pw-browsers/chromium
 curl 금지 (렌더러가 아니다)


A6  단발 캡
 단발 지시 = 받은 지 10분 안에 결론.

 평의회·배치·파이프라인이 붙는 일은
 D3 봉투가 이 캡을 대체한다.


※ A1~A6이 곧 착수 게이트다.
  별도 검문 조항은 두지 않는다.
  (규칙 + 규칙의 검문 = 이중층 = 비대화)

  각 항은 "했는가?"로 읽는다.
  A1엔 완료판정 1줄,
  A5엔 before 스샷 파일 1장이
  증거로 남아야 ✅다.


──────────────────────────
 §B  수행 중 (디자인·실행 규율)
──────────────────────────

B1  창작 금지
 디자인 코드·색·값은 임의 제작하지 않는다.

 착수 1줄에 「레퍼런스 = X 그대로」를
 지목해 100% 모방한다. (99% = 0%)

 색·값은 【레포 바인딩】의
 토큰 SSOT 계승만 허용.
 (새 hex·px 창작 = 실패)

 지목할 레퍼런스가 정 없으면
 만들지 말고 B3 시안을 선행한다.


B2  정렬
 디자인에서 가장 중요한 것은 정렬이다.

 정렬 = 대상을 4분할한 중심점이
 동일한 가로선 또는 세로선에 있는 것.

 실렌더 getBoundingClientRect로
 픽셀 실측해 증명한다. (허용 오차 ≤1px)

 증빙 = 4분할 중심좌표 표
 (요소 · centerX/Y · 오차px)


B3  플레이그라운드
 발동 조건 = 모방할 레퍼런스를 지목 못 하거나
 배치 후보가 2안 이상 갈릴 때 한정.

 미리보기 영역을 고정한 채
 요소를 만지는 자기완결 HTML.
 (PC 좌/우 · 모바일 상/하)

 선택지는 대분류 5축 × 축당 10안으로
 조직한다.
 (옵션 총량 쿼터가 아니다
  — 한 요소를 잘게 쪼개 나열 금지)

 이미 정립된 값은 '고정' 배지로 표시해
 이탈을 억제한다.


B4  신규 등장 요소
 화면에 새로 생기는 컨트롤·칩·배지는
 ⓐ 그 요소만 단일 커밋 분리
 ⓑ 보고에 ⚠배치 (어디·어떤 모양 1줄)
 ⓒ "이 위치·모양으로 해석했다
    — 의도 맞나?"를 먼저 붙인다.


B5  다중 대상 지시
 '전 파일/전 레포에 X 적용' = 맹목 일괄 금지.

 대표 1개 먼저 실측하고,
 갭 있는 데만 적용한다.
 없으면 보고한다.


B6  정본 신설 금지
 참조할 정본은 【레포 바인딩】에서 찾는다.

 바인딩에 없으면 그 레포엔 '없음'이며,
 새로 모으거나 만들지 말고 먼저 제안한다.
 (이미 있는 정본을 다시 모으면
  라이브·게이트가 끊긴다)


──────────────────────────
 §C  완료 시 (보고 게이트)
──────────────────────────

C1  보고 = 6단 골격 그대로, 항상
 (순서 고정 · 사족·장식 섹션 금지)

 ① 질문
    지시 원문 인용

 ② 의도파악
    목적 · 배경 · 문제정의

 ③ 결론: 성공/실패
    볼드. 완벽 수행이 아니면 '실패'.
    + 3줄 초등학생 요약
      (문장마다 줄바꿈)
      1줄차 = 성공/실패 + 무엇
      2줄차 = 뭐가 달라졌나
      3줄차 = 다음 액션 or '없음'

 ④ 처리 결과
    A2 표에 ⑨ 채워 재게시
    + 전 → 후 비교
      (디자인 = before/after 스샷)
    + 머지 여부
    + 평의회 결과

 ⑤ 수행 체크리스트
    발동 항목별
     ✅ 증거 1줄
     ⚠ 미검증 + 사유
     ⬜ 미수행
     N/A + 발동조건
    행 누락·증거 없는 ✅
     = 그 보고 자체가 미완

 ⑥ 💡 한 수 1개
    work to do · 리스크 포함.
    억지 금지.
    진짜 없으면 '없음' + 사유 반 줄.
    기존·신규 작업물 품질을
    절대 떨어뜨리지 않을 것.


 ※ 판정원은 하나다.
   C1-⑤ 체크리스트가 유일한
   성공/실패 판정 근거다.
   (C2~C4는 그 체크리스트의 행일 뿐,
    별도 관문이 아니다)

   체크리스트는 보고 ④ 끝에
   3칸 표로 고정한다.
   (항목 | 한 줄 요약 | ✅/⚠/⬜/N-A)
   O/X 열만 훑으면 성공/실패가 보인다.


C2  디자인 렌더 영수증 (이원 판정)
 디자인을 바꿨으면
 바꾸기 전·후를 각 1장 렌더해 첨부한다.

 렌더 불가 시
 「⚠미실측(코드추정)」 + 못 본 항목 명시.

 둘 중 하나가 없으면 미완이다.
 (추정을 완성으로 포장 금지
  — 검증은 가능할 때만, 정직은 항상)


C3  머지
 보고와 함께 Draft PR을 바로 머지한다.

 단 다음은 예외다.
 ⓐ D3 평의회 발동 조건이면
   평의회 통과 후
 ⓑ D2 비가역·파괴·과금은
   승인 후
 ⓒ 자동 전파(sync) PR은
   세션이 머지하지 않는다

 '완료' = main 머지 +
 git show origin/main:<파일> read-back
 후에만 선언한다.
 (완료 시점 예고 금지 — 실측 후 보고만)


C4  게이트
 커밋 전 【레포 바인딩】의
 상비 게이트 rc=0 필수.

 clone·기기마다 1회
 훅 활성화를 확인한다.
 (미설정이면 게이트가 조용히 미실행되고
  "통과했다"는 착각으로
  깨진 커밋이 들어간다)

 미확인이면 그 작업은 '실패'로 보고한다.


──────────────────────────
 §D  금지·승인
──────────────────────────

D1  스케줄링 금지
 지시 없는 예약·크론·백그라운드·
 자가 체크인·임의 병렬 금지.

 기계 차단 = 【레포 바인딩】 훅.
 이 문장은 요약이고 훅이 먼저 막는다.

 예외 = D3 평의회.
 규칙이 시키는 병렬 소환과 그 완료 대기는
 위반이 아니다.


D2  승인
 비가역·파괴 작업과 신규 과금 경로는
 실행 전 무조건 묻는다.

 비가역·파괴 =
  데이터·백업 삭제,
  히스토리 재작성,
  미머지 커밋을 날리는 git checkout -B

 승인은 채팅 문답만 인정한다.
 (팝업 수락 ≠ 승인)

 이미 승인된 일의 분기 선택은
 버튼으로 받아도 된다.


D2-1  기계산출물 손편집 금지
 스크래퍼·크론·빌더가 생성하는
 데이터·거울 파일은
 세션이 손으로 고치지 않는다.
 (손편집 = 자동커밋과 병합 레이스)

 값 변경 = 생성하는 코드를 고친다.

 대상 목록 = 【레포 바인딩】


D2-2  롤백 1줄
 리스크 칸에 되돌리는 법
 (revert 대상 커밋)을 반드시 적는다.

 롤백 경로가 없는 변경은 착수하지 않는다.


D3  평의회
 ① 발동
   사용자가 검증·평의회를 요청하거나,
   【레포 바인딩】의 평의회 대상 경로를
   건드린 경우.
   (자기판단 아님
    — 목록에 있으면 무조건,
      없으면 소집하지 않는다)

 ② 방법
   서로 다른 관점의
   OPUS 5 최고노력 8인 병렬 적대 검증.
   READ-ONLY
   (커밋·브랜치·PR은 메인 세션만)

   소집 전 nproc 1줄로
   동시 슬롯(코어−2)을 실측한다.

   좌석이 슬롯을 넘으면
   {좌석 축소 · 봉투 사전 고지 ·
    툴 사용 최소화} 중 택1.

 ③ 봉투
   T0 기준 8분 하드스톱 하나.
   (이중 마감 없음)

   초과분은 폐기가 아니라
   그때까지 회수된 것으로 수렴한다.


D3-1  확인·처리 상태
 ✓ack · seen · 뮤트 · dismiss는
 계정 종속이 기본값이다.

 기기 localStorage 단독 저장 금지.
 (로컬 = 즉시성 캐시)

 정본·구현 경로 = 【레포 바인딩】

 알림·확인 UI는 설계 시점에 배선한다.
 (사후 이식 금지)


D4  시각
 전부 KST.

 러너는 UTC이므로
 TZ='Asia/Seoul' 강제.

 코드에 시각을 심을 때도
 naive new Date() · utcnow() 금지.

  이미 모으기를 끝냈다.

 왜 뒤집었나
  이 환경은 4코어다.
  동시 슬롯 = 코어−2 = 2석.

  8인을 동시에 시작하면 직렬화된다.
  (과거 실측 = 런 51분)

  A안대로면 평의회가 매번 자동 폐기되어
  태운 토큰이 전량 소각된다.

  ※ 참고: 이번 세션은
    툴 사용을 최소화해 8분 안에
    16인 전원 회수에 성공했다.
    A안을 살리려면
    이 "툴 최소화" 조건을
    문서에 명문화해야 한다.

── 되살린 안전축 (초안에서 빠져 있던 것)

 · SYNC-COMMON 마커
   없으면 전 레포 전파 즉시 정지

 · 【레포 바인딩】 정본 경로
   없으면 매번 값 추측 = 값 창작

 · 상비 게이트 + hooksPath 확인
   없으면 41게이트 조용한 미실행

 · 기계산출물 손편집 금지
   없으면 크론과 병합 레이스 재발

 · 비가역·파괴·과금 승인
   초안엔 승인 게이트가 0개였다

 · 계정 종속 상태 (ack/seen)

 · 렌더 영수증 이원 판정
   전후 스샷 or ⚠미실측 딱지


── 해소한 자기모순

 · 병렬 금지 vs 8인 병렬
   → 평의회를 명시 예외로

 · 실패 판정 폭주
   (조건 안 걸린 조항까지 미수행=실패)
   → N/A 축 신설

 · 보고 형식 2개 (8항 + 3줄)
   → 6단 단일, 3줄은 ③ 안으로 흡수

 · 8분 / 10분 이중 마감
   → 8분 하나

 · 종료시각 예고 vs 예고 금지
   → 상대값만

 · 50개 쿼터
   → 대분류 5 × 소분류 10 조직

 · 정본 재수집
   → 신설 금지, 참조만


── 구조

  → §0 전달계약
    A 착수

    C 완료
