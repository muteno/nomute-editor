결론 — 이상한 건 「전송버튼」이 아니라 「동그란 수정 FAB」이고, 3트에서 색이 원본으로 되돌아간다.
  1. 회차 색은 revColor(g) = RV_COLORS[g % 3] — 3칸짜리 순환이다(index.html:6418).
  2. 그래서 3트 = 3 % 3 = 0번색 = 터쿼이즈, 그런데 터쿼이즈는 0트(수정 안 한 원본) FAB의 기본색 --accent #00EED2과 같은 색이다. → 3번 고쳤는데 화면은 "한 번도 안 고친 것"처럼 보인다.
  3. 전송버튼(#revSend/#crevSend)은 회차를 아예 안 본다 — 1트든 3트든 수정 → 재확인 → 게이지 → ✓ 로 완전히 동일.

① 뉴스 요약 수정 FAB (#revFab · 연필) — 수정 완료 상태

클래스 = .rev-fab.revdone + --rv-solid: revColor(a.rev) (index.html:6509·6515)

② 카드뉴스 프롬프트 수정 FAB (#crevFab · 카드스택) — 수정 완료 상태

완전히 같은 함수 사다리(applyCrevFab index.html:7275) · 회차만 a.cards.crev로 독립 · 3트 되돌아감 증상도 똑같이 있음

③ 수정 요청이 "진행 중"일 때 (물결 = 현재색 ↔ 다음색 왕복)

클래스 = .rev-fab.revving.locked + --rv-from: revColor(g) / --rv-to: revColor(g+1) (index.html:6511~6513)
