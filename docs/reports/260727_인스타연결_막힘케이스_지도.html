인스타 연결 — 막히는 자리 전부

260727 · 스크린샷(“Facebook 개발자로 등록해야 합니다”)에서 출발한 15케이스 지도. 절차 정본은 docs/인스타_직결_세팅.md이고, 이건 그 문서 §8을 넓힌 보조 지도다.

한 줄 답 — 네가 연 창은 인스타랑 상관없는 창이다.

“사람 추가 및 권한 설정”은 비즈니스 포트폴리오에 페이스북 계정을 붙이는 화면이야. 인스타 계정은 여기 안 붙는다(그래서 “개발자로 등록하라”고 튕긴 것). 인스타는 앱 대시보드 → 앱 역할 → 인스타그램 테스터에서 붙인다. 아래 C1이 그 케이스.

0. 표기 약속 — 뭘 믿고 쓴 값인지

정본 레포 문서·코드에 이미 있던 것(내가 파일을 열어 확인) · 웹 이 세션에서 검색·Meta 공식문서로 확인 · 미확인 근거 없음, 안 해봄.

지어낸 값은 없다. 확인 못 한 건 §6에 그대로 남겼다.

2. 막힘 케이스 15개

C1. “앱에 액세스하려면 이 사람이 Facebook 개발자로 등록해야 합니다” 지금 이거

증상 — 비즈니스 관리자 “사람 추가 및 권한 설정”에서 인스타 계정을 고르면 툴팁이 뜨고 할당 버튼이 안 살아난다.

원인 — 화면을 잘못 열었다. 이 창은 비즈니스 포트폴리오에 사람(페이스북 계정)을 붙이는 곳이라, 인스타 계정은 애초에 대상이 아니다. 목록에서 페북 아이콘 붙은 본인은 “이미 할당됨”인데 인스타 아이콘 쪽만 막히는 게 그 증거. 웹

해결

  1. 이 창 닫는다.
  2. developers.facebook.com/apps/<앱ID>/roles/roles/ 직행 (대시보드 좌측 앱 역할 → 역할).
  3. 인스타그램 테스터 섹션 → 사람 추가 → 인스타 사용자명 입력 → 상태 “대기 중”.
  4. 인스타 쪽에서 수락(→ C3).

※ 페북 계정 자체가 개발자 등록이 안 돼 있어서 진짜로 필요할 때만: developers.facebook.com/async/registration (전화·이메일 인증 1회). 웹

C2. OAuth 팝업 “개발자 역할 권한 부족”(insufficient developer role) 자주

증상 — 토큰 발급하려고 계정 추가를 누르면 로그인 팝업이 이 에러로 끝난다.

원인 — 앱이 개발 모드면 “앱에 역할이 있는 계정”만 인증을 통과한다. 테스터 초대를 아직 안 했거나, 초대는 했는데 수락을 안 했다. 정본 웹

해결 — C1의 3)~4)를 끝내고 재시도. 순서를 꼭 지켜라: 초대 → 수락 → 그 다음 토큰 발급.

C3. 인스타에 “테스터 초대” 탭이 안 보인다 자주

증상 — 설정을 아무리 뒤져도 초대 수락할 데가 없다.

원인 — 인스타 앱(모바일) 설정에는 이 메뉴가 잘 안 뜬다. 웹 전용 경로다. 정본

해결 — 웹 브라우저로 instagram.com/accounts/manage_access/ 직행 → 테스터 초대(Tester Invites) 탭 → 수락. (앱 설정의 “앱 및 웹사이트 권한” 경로도 같은 지점으로 간다.)

C4. 엉뚱한 계정으로 인증돼 버린다 자주

증상 — 분명 초대·수락 다 했는데 계속 권한 부족. 또는 다른 계정이 연결된다.

원인 — 브라우저에 인스타 멀티 계정이 로그인돼 있으면 팝업이 엉뚱한 세션을 집는다. 정본 웹

해결 — 시크릿 창에서 대상 계정만 로그인한 상태로 처음부터. (웹 사례에서도 “같은 세션에선 실패, 시크릿 창에선 바로 됨”이 반복 보고된다.)

C5. 옛날에 붙였던 앱 잔재가 꼬여 있다 드묾

증상 — 새로 연결하는데 이유 없이 실패하거나, 권한이 이상하게 적게 잡힌다.

원인 — 과거 연결·만료된 승인이 계정에 남아 스테일 상태. 정본

해결 — instagram.com/accounts/manage_access/에서 그 앱의 기존 연결을 제거하고 처음부터 다시.

C6. “the user is not an instagram business” 자주

증상 — 토큰은 나왔는데 API가 이 메시지로 거절.

원인 — 개인 계정이다. API는 프로페셔널만 받는다. 웹

해결 — 인스타 설정 → 계정 유형 → 비즈니스 또는 크리에이터 전환 후 재연결. 판별 요령: 앱에서 인사이트 화면이 보이면 이미 프로페셔널이다. 정본

C7. 권한을 일부만 승인해서 기능이 반쪽 자주

증상 — 조회는 되는데 게시가 안 된다(“Not enough permissions to post”). 인사이트만 빈다.

원인 — 로그인 팝업에서 스코프 체크를 일부 껐다. 나중에 체크만 추가로 켤 수는 없다. 웹

해결 — 페이스북 비즈니스 통합(Business Integrations) 또는 인스타 manage_access에서 그 앱 연동을 제거 → 다시 로그인하며 전부 체크. 읽기 최소 조합 = instagram_business_basic + instagram_business_manage_insights, 게시까지면 instagram_business_content_publish. 정본

C8. 60일 뒤 갑자기 다 죽는다 자주

증상 — 잘 돌던 자동 수집이 어느 날 통째로 실패.

원인 — 장수명 토큰 수명이 60일. 만료되면 끝이다. 정본

해결(2가지)

  • 수동 — API 설정 화면에서 Generate token 다시 → 시크릿 값만 교체(2분). 정본
  • 자동 — GET https://graph.instagram.com/refresh_access_token?grant_type=ig_refresh_token&access_token=<토큰> 을 만료 전에 호출하면 그날부터 다시 60일. 조건 = 토큰이 24시간 이상 경과 + 아직 안 만료 + instagram_business_basic 보유. 웹

⚠ 만료된 뒤엔 갱신이 안 된다 — 죽고 나서 부르면 늦는다.

C9. 토큰이 살아있어야 할 시점인데 무효 드묾

증상 — REVOKED_ACCESS_TOKEN / “session has been invalidated”.

원인 — ① 인스타 설정에서 앱 권한을 뺐거나 ② 비밀번호를 바꿨거나 ③ 보안 확인을 거쳤다. 셋 다 세션을 끊는다. 웹

해결 — 재연결 후 토큰 재발급. → 비번 바꾸면 토큰도 갈아야 한다는 것만 기억하면 된다.

C10. “Error validating access token” 드묾

증상 — 발급 직후인데 검증 실패.

원인 — 계정이 미확인 상태(이메일·전화 인증 미완). 웹

해결 — 페이스북/인스타에서 이메일·전화 확인 끝낸 뒤 재연결.

C11. 해시태그 검색·남의 계정 지표가 필요해졌다 경로 갈아타기

증상 — 아무리 해도 해시태그 미디어 조회 엔드포인트가 없다.

원인 — Instagram 로그인 경로엔 애초에 없는 기능이다. 웹

해결 — Facebook 로그인(비즈니스) 경로로 전환: 인스타를 페이스북 페이지에 연결 → graph.facebook.com의 페이지 → instagram_business_account 경유. 우리 레포엔 이 비교를 실제로 쏴보는 진단 스크립트가 이미 있다(§5). 정본

C12. 팔로워 인구통계가 빈다 드묾

증상 — follower_demographics만 계속 비어서 온다.

원인 — Meta 제한: 팔로워 100명 이상부터 제공. 정본

해결 — 없음(기다린다). 버그로 오해하지 말 것.

C13. 지표 이름이 어느 날 사라진다 자주

증상 — 잘 되던 impressions가 에러. 묶음 요청이 통째로 실패.

원인 — Meta가 지표를 개폐한다(impressions → views 이관이 실제 사례). 게다가 지표마다 요구 파라미터가 갈린다(period=day+metric_type=total_value / period=day / period=lifetime). 정본 실측

해결 — 묶음으로 쏘지 말고 낱개 폴백으로 살아있는 지표만 건지고 죽은 건 기록. 우리 insta_fetch.py가 이미 이 구조다.

C14. 남의 계정까지 서비스하려면 큰 벽

증상 — 개발 모드에선 테스터로 넣은 계정만 된다. 실사용자를 못 받는다.

원인 — 라이브 전환 = 앱 심사(App Review) 필수. 권한 스코프마다 용도를 보여주는 화면녹화 영상을 제출해야 하고, 비즈니스 인증엔 사업자 서류가 든다. 웹

해결 — 일정부터 잡아라. 표준 권한 심사 2~4주, 출시 계획엔 6~8주를 잡으라는 게 통설. 본인 계정만 쓸 거면 이 벽은 아예 안 만난다(Standard Access).

C15. 요청이 자꾸 막힌다(레이트리밋) 운영 단계

증상 — 429 / 80002 / “Instagram blocked your request”.

원인 — 비즈니스 사용 사례(BUC) 기준 쿼터. 노출이 적은 계정일수록 한도가 빡빡해 예측이 어렵다. 게시는 일 100개 상한. 웹

해결 — 15~30분 backoff 후 재시도 + 호출 분산. 우리처럼 하루 1회 배치면 사실상 안 만난다.

3. 토큰 4종 — 뭘 쓰느냐로 운영 부담이 갈린다

※ 마지막 줄이 “60일마다 갈아끼우기”를 없애는 유일한 정공법이다. 대신 비즈니스 인증(사업자 서류)이 선행이고, 이 세션에서 실제로 해보지는 않았다 미확인. 참고로 네가 처음 연 그 “사람 추가” 화면이 바로 이 축(비즈니스 포트폴리오)에 속한다 — 방향 자체가 아주 틀린 건 아니었고, 지금 단계에 필요한 화면이 아니었을 뿐이다.

5. 우리 레포는 지금 어디까지 와 있나 실측

  • 경로 = Instagram 로그인(§1 왼쪽 열) · 호스트 graph.instagram.com
  • 인증 = GitHub 시크릿 IG_ACCESS_TOKEN 하나 (없으면 no-op exit 0로 조용히 넘어감)
  • 수집기 = .github/scripts/insta_fetch.py — stdlib only · 지표 낱개 폴백 내장(C13 대응) · 토큰 원문 저장 안 함(sha256 꼬리 12자만)
  • 배치 = .github/workflows/insta-fetch.yml · 매일 06:25 KST
  • 산출 = apps/insta/data/ {insights_daily.jsonl · media_latest.json · audience.json · token_meta.json}
  • 경로 비교 진단기 = .github/scripts/ig_probe.py — FB_PAGE_TOKEN(페북 경로)와 IG_ACCESS_TOKEN(인스타 경로)에 같은 지표를 쏴서 생존/사망 판정. READ-ONLY·산출 없음 → C11 갈아타기 검토할 때 여기부터
  • 과거 시드 = apps/insta/insta_history_import.py로 수동 CSV를 소급 병합(2025-11~)
  • 절차 정본 = docs/인스타_직결_세팅.md — 값이 이 문서와 갈리면 정본이 이긴다

→ 즉 no_mute 계정은 이미 붙어서 돌고 있다. 지금 Lucy 앱에서 하려는 건 그것과 별건이라, C1대로 앱 역할에서 테스터를 넣는 게 맞는 출발점이다.

6. 아직 모르는 것 — 지어내지 않은 부분

  • Lucy 앱을 어디에 쓸 건지 못 들었다. 본인 계정 수집·게시면 C1~C8로 끝이고, 남의 계정까지면 C14(심사 2~4주)가 붙는다. 여기서 필요한 준비물이 완전히 갈린다. 미확인
  • 시스템 사용자 무기한 토큰은 공식문서 근거만 있고 이 세션에서 실제로 발급해보지 않았다. 비즈니스 인증 서류 심사가 어느 정도 걸리는지도 모른다. 미확인
  • Meta UI 문구는 개편이 잦다. 여기 적은 메뉴 이름과 화면이 다르면 그 화면 스샷을 던져주면 짚어준다. 정본과 동일 단서
