SNS 수집 복구 절차

알림 3건 중 2건은 저절로 풀렸고, 남은 건 네 손이 필요한 두 가지다. 순서대로 따라 하면 인스타 큐레이션이 살고 새벽 끊김이 끝난다.

SNS 트렌드 정체 94분 해결됨 03:49 수집 정상 — 워치독이 다음 런에서 알림을 자동으로 내린다.
스레드 구독 안 걷힘 해결됨 폰이 살아나면서 15건 수집 — 쿠키가 이미 들어가 있어서 폰만 돌면 걷힌다.
인스타 구독 안 걷힘 트랙 1 폰은 도는데 인스타만 0건. 계정 20개를 등록해두고 한 번도 못 걷은 상태다.
새벽 폰 정지 (2시간) 트랙 2 00:32~02:25 공백. 안드로이드 도즈가 crond를 재운 것으로 보인다.

트랙 1 — 인스타 쿠키 넣기

폰에서 · 한 줄 · 넣으면 30분 안에 큐레이션에 뜬다

  1. 인스타 부계정으로 로그인해서 쿠키 3개를 뽑는다

    PC 브라우저에서 부계정으로 instagram.com 로그인 → 개발자도구(F12) → Application → Cookies → sessionid, ds_user_id, csrftoken 세 값을 복사.

    본계는 쓰지 마. 자동화 감지에 걸리면 계정이 밴된다. 수집기는 30분마다 20개 계정을 순회하니 반드시 버려도 되는 계정으로.

  2. 폰 시크릿 파일에 한 줄 덧붙인다

    termux

    아래를 붙여넣고 … 자리에 1단계에서 복사한 값을 채운다. >>(덮어쓰기 아님)라서 기존 스레드 쿠키는 그대로 남는다.

    echo 'export INSTA_COOKIE="sessionid=…; ds_user_id=…; csrftoken=…"' >> ~/.nomute_phone_env

    이 파일은 git 밖이라 레포에 안 올라간다. 권한은 스크립트가 실행할 때 자동으로 600으로 잠근다.

  3. 바로 한 번 돌려서 확인한다

    termux
    bash ~/nomute-editor/scripts/phone_subs.sh && python3 -c "import json;print('insta',len(json.load(open('$HOME/nomute-editor/viewer/sns_subs_phone.json'))['insta']),'건')"

    insta 0건이 아니면 성공. 여전히 0이면 쿠키가 만료됐거나 csrftoken이 빠진 것 — 세 값을 다시 뽑아 2단계를 다시 한다.

쿠키를 넣으면 뭐가 되고, 뭐는 안 되나

된다 — 네가 등록한 20개 계정(국내 10 · 해외 10)의 최신 릴스가 조회수 순으로 걷힌다. 화면에서는 큐레이션 → 인스타그램 소분류에 카드로 뜬다.

안 된다 — 인스타 전체의 "인기 게시물"이나 탐색 탭은 못 가져온다. 수집기가 보는 건 네가 구독한 계정의 타임라인뿐이라, 등록 안 한 계정 글은 영영 안 들어온다.

화면 배선은 이미 다 되어 있다. 지금은 데이터가 0건이라 빈 섹션이 조용히 숨어 있을 뿐 — 데이터가 차는 순간 코드 수정 없이 자동으로 나타난다.

트랙 2 — 새벽에도 폰이 돌게

3층을 다 해야 안 끊긴다 · 1·2는 네 손 · 3은 코드에 이미 넣었다

  1. Termux:API 앱을 설치한다

    F-Droid + termux

    F-Droid에서 Termux:API 앱을 깔고, termux에서 CLI도 깐다. 둘 다 있어야 웨이크락이 동작한다 — 앱 없이 CLI만 깔면 조용히 아무 일도 안 일어난다.

    pkg install termux-api

  2. 배터리 최적화에서 Termux를 뺀다

    안드로이드 설정

    설정 → 배터리 → 앱 배터리 관리 → Termux → 제한 없음.

    이건 웨이크락으로 못 막는 층이다. 웨이크락은 CPU가 자는 걸 막지만, 시스템이 앱 자체를 죽이는 것은 이 설정으로만 막힌다.

  3. 스크립트를 최신으로 당긴다 코드 완료

    termux

    수집 스크립트가 실행될 때마다 스스로 웨이크락을 잡도록 넣어놨다. 아래로 최신본을 받으면 다음 크론부터 적용된다.

    cd ~/nomute-editor && git pull --rebase origin main

    웨이크락은 일부러 해제하지 않는다. 놓는 순간 다시 도즈로 들어가 같은 공백이 재발하기 때문 — 대신 배터리를 더 먹는다. termux-api가 없는 환경(맥 등)에서는 조용히 건너뛰고 종전대로 돈다.

왜 하필 폰인가

읽을거리 — 할 일 없음

메타(인스타·스레드)는 데이터센터 IP를 차단한다. 그래서 GitHub 러너도, 이 작업 컨테이너도 전부 0건을 받는다. 가정용 IP인 네 폰만이 유일한 통로다.

GitHub 러너→ 컨테이너→ 폰 (termux)→ sns_subs_phone.json→ 화면

그래서 폰이 멈추면 스레드 · 인스타 · 레딧 · 재난문자 넷이 동시에 굶는다. 다른 소스(X · 틱톡 · 유튜브)는 서버가 직접 걷어서 폰과 무관하다.

임계값뜻
폰 크론 주기30분이 주기로 폰이 수집해서 올린다
서버 채택 게이트90분폰 파일이 이보다 낡으면 서버가 안 받는다 = 굶기 시작
폰 경보 임계90분오늘 3시간 → 90분으로 낮춤 · 굶는 순간 바로 알림

전에는 경보가 3시간이라 90~180분 사이엔 데이터가 굶는데도 알림이 조용했다. 이번 2시간 정지가 정확히 그 구간이라 "스레드·인스타가 안 걷힌다"만 뜨고 진짜 원인인 폰 정지는 안 보였다. 이제 그 공백이 없다.
