# 스레드 직결 세팅 — 루시 자동 운영 (Threads API · 운영자 260726)

> 루시 페르소나 계정이 **AI 지식을 스레드에 자동 발행 + 답글 자동**하는 설비. 밤 전용 저빈도.
> `.github/workflows/lucy-threads.yml` → `.github/scripts/lucy_threads.sh` → `.github/scripts/threads_api.py` → `viewer/threads_state.json`.
> 원료 = `viewer/sns_trends.json`(30분 크론 · `hackernews`=해외 AI 원문 / `aivid`=국내 AI 소식) — **읽기만**(D2-1 준수 · 수집기 무접촉).
> 게이트 미충족 = 조용한 no-op(rc 0 = 실패 아님). 자매 문서 = `docs/페이스북_직결_세팅.md`(같은 Meta 앱 재사용).

## ⚡ 빠른 시작 — 남은 건 이 4스텝 (레포 쪽 설비 = 100% 상비 완료)

1. **루시 스레드 계정 확보** — 인스타 부계 신규 생성 → 스레드 가입(계정 생성은 API가 없어 수동만 가능).
2. **앱에 Threads 유스케이스 추가** — https://developers.facebook.com/apps → `nomute-insights`(ID `1522670392977528`)
   → 유스케이스 추가 → **Threads API 액세스** → 권한 4종 체크:
   ```
   threads_basic
   threads_content_publish
   threads_read_replies
   threads_manage_replies
   ```
3. **테스터 초대 → 수락 → 토큰 발급** — 앱 역할에 루시 계정을 **Threads 테스터**로 초대 → 루시 쪽에서 수락
   → 같은 화면에서 장기(60일) 토큰 생성. ⚠ **할당·수락 먼저, 토큰은 그 다음**(먼저 만든 토큰은 옛 권한이라 안 붙는다 · FB §6 동일 함정).
4. **등록 2값** —
   | 구분 | 이름 | 값 | 등록 URL |
   |---|---|---|---|
   | **Secret** | `THREADS_ACCESS_TOKEN` | 3의 장기 토큰 | https://github.com/muteno/nomute-editor/settings/secrets/actions |
   | **Variable** | `LUCY_ON` | `1` = 가동 / `0` = 정지 (**기본 0**) | https://github.com/muteno/nomute-editor/settings/variables/actions |

   ⚠ 토큰은 시크릿 칸에만 — 채팅·파일·커밋에 절대 붙여넣기 금지.

## 0. 앱 검수(App Review) 불요 — 근거

Threads API는 **본인 계정 + 테스터로 등록한 계정**에 한해 발행이 열린다. 공개 검수(2~6주)는 **남의 계정을 대신 게시**할 때 필요하다.
루시는 단일 자기 계정이라 **테스터 등록으로 끝난다.**
⚠ 페이스북 **페이지** 게시(`pages_manage_posts`)는 이와 달리 검수 대상이다 — 축이 다르니 혼동 금지.

## 1. on/off = 설정 1값 (운영자 260726 "얘는 설정에서 on off할수있게")

`LUCY_ON` repo Variable 하나가 전원 스위치다. `0`이면 워크플로는 돌되 **claude 호출 전 즉시 exit 0**(LLM 쿼터 0·API 호출 0).
나머지 기존 러너(fb-fetch·insta-fetch·sns-trends…)는 **무접촉 = 실가동 그대로**.

| 변수 | 기본 | 뜻 |
|---|---|---|
| `LUCY_ON` | `0` | 전원. `1`로 바꾸면 다음 밤 크론부터 가동 |
| `LUCY_REPLY_CAP` | `8` | 1회 실행당 답글 상한(스팸 방어) |

## 2. 스케줄 (밤 전용 · 한 수 채택 260726)

| cron(UTC) | KST | 슬롯 |
|---|---|---|
| `0 14 * * *` | 23:00 | **both** = 발행 1건 + 답글 스윕 |
| `30 16 * * *` | 01:30 | **reply** = 답글만(밤 발행 뒤 붙은 답글 회수) |

수동 = Actions → `lucy-threads` → `Run workflow` (슬롯 선택 + **드라이런 체크** 가능).

## 3. 드라이런 — 말투 튜닝은 여기서

`Run workflow` → `dry_run` 체크 = **실제 발행 안 하고 "이런 글이 나갔을 것"만 로그로 출력**.
페르소나 말투가 스레드에서 어떻게 읽히는지 **계정 정지 리스크 0으로** 반복 튜닝할 수 있다. 만족스러우면 체크만 풀면 된다.

## 4. 재답글 스팸 차단 — 이 설비의 핵심 안전장치

러너는 실행마다 기억이 없다. 상태 없이 짜면 매일 밤 **같은 답글 25개를 재수집해 같은 사람에게 반복 답글** → 스팸 판정 → 계정 정지.
(가상인물 다계정 자동화가 실제로 이걸로 정지당한 선례가 있다.) 그래서 `viewer/threads_state.json`을 **커밋으로 영속**시킨다.

| 층 | 장치 |
|---|---|
| ① | `replied[]` — 답글 단 id 영구 기록 |
| ② | 내 username 필터 — **자문자답 루프 차단**(내 id 미해석 시 아예 중단) |
| ③ | `replied_users{}` — 같은 사람 1일 1회 |
| ④ | `LUCY_REPLY_CAP` — 1회 실행당 상한 |

⚠ 이 파일은 러너 산출이다 — **손으로 고치지 마라**(D2-1). 되돌리려면 해당 항목을 지우는 게 아니라 파일 자체를 지운다(= 전량 재답글 위험이니 권장 안 함).

## 5. 페르소나 카드

`persona/lucy_threads.md` = 주입 슬롯. 지금은 플레이스홀더라 **러너가 LLM 호출 전 중단**한다(카드 없이 말투를 지어내면 루시가 아니므로).
YETA 카드 원문을 이 파일에 통째로 붙이면 즉시 가동. 스크립트는 이 파일을 **원문 그대로** 프롬프트에 주입하므로 카드만 고치면 말투가 자동 추종한다(코드 수정 0).

## 7. 한계·미검증 (정직)

- 실 발행·실답글은 **계정·토큰 미존재로 미실측**. 첫 가동은 반드시 **드라이런 → 수동 both 1회** 순서로.
- `/{id}/replies` 응답 스키마 = 공식 문서 기준 구현. 첫 스윕 로그에서 실물 확인 필요.
