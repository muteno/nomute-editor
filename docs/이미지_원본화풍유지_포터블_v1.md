# 포터블 — 원본 화풍을 지키면서 표정·자세만 바꿔 뽑는 법 v1

> **다른 레포로 그대로 가져가 쓰라고 뽑은 문서.** 이 레포 경로·이름에 안 묶여 있다.
> **근거**: 260726 이 레포에서 **한 번 실패하고 한 번 성공한** 실측. 이론이 아니라 픽셀로 잰 값이다.

---

## 0. 한 줄 요약

**첨부 이미지를 넣는 것만으로는 원본 화풍이 안 지켜진다.** 프롬프트에 아트 스타일을 한 줄이라도
쓰면 모델은 **첨부보다 그 글을 따른다**. 지켜야 할 것은 ①스타일 낱말 0개 ②`input_fidelity: high`
③칸을 정사각에 가깝게 — 이 셋이다.

---

## 1. 실패와 성공 — 같은 캐릭터, 같은 원본, 프롬프트만 다름

원본 얼굴과 생성 컷을 256×256으로 맞춰 잰 값이다.

| 지표 | 원본 | ❌ 실패본 | ✅ 성공본 |
|---|---|---|---|
| 선 강도(라플라시안 평균) | 10.5 | 18.0 **(+71%)** | 9.6 **(−9%)** |
| 굵은 선 비율(>110) | 2.5% | 5.2% **(+2.7%p)** | 2.1% **(−0.4%p)** |
| 상위 8톤 점유 | 51.4% | 76.7% **(+25.3%p)** | 61.8% (+10.4%p) |
| 평균 채도 | 158.8 | 137.4 (−13%) | 163.9 **(+3%)** |

**실패본에서 무슨 일이 났나**: 원본에 없던 **굵은 검정 아웃라인**이 생기고(선 +71%), 부드러운
그라데이션이 **평면 덩어리로 계단화**(상위 8톤 +25%p)됐다. 캐릭터 4인 전체로는 선 +117~177%,
톤 +21~46%p까지 갔다. 사람 눈에는 "왜 갑자기 애니풍이 됐지?"로 보인다.

**정체성도 같이 날아간다**: 한 캐릭터는 좌우 눈 색이 다른 설정이 소실됐고(그 캐릭터의 존재 이유였다),
다른 캐릭터는 피부의 문양과 밤 조명 배경이 통째로 사라져 단색 판이 됐다.

## 2. 원인 4층 (중요도 순)

### L1. ⛔ 프롬프트의 아트 스타일 문장 — 첨부보다 세다
실패본 프롬프트에 이런 문장이 있었다:
> "아트 스타일: 또렷한 라인아트 + 평평한 셀 채색, 수채·유화 질감 금지"

**선 +71%·톤 계단화가 정확히 이 문장의 픽셀 서명이다.** 모델은 첨부 이미지를 참고 자료로 보고,
글로 쓴 지시를 명령으로 본다. 둘이 충돌하면 글이 이긴다.

**⚠ 함정**: "화풍은 원본 그대로"라고 써 놓고 **바로 뒤에** 스타일을 설명하면 소용없다.
실패본은 실제로 그렇게 쓰여 있었다.

**⚠ 더 미묘한 함정**: 지키라고 **열거하는 것도** 위험하다. "그림체·채색 방식·붓질 질감·선 굵기를
바꾸지 마라"처럼 축을 나열하면 모델이 그 축을 **의식하고 손을 댄다**. 성공본은 열거를 빼고
한 줄로 대체했다 — **"여섯 칸 전부 첨부 그림과 같은 파일에서 잘라낸 것처럼 보여야 한다."**

### L2. ⛔ `input_fidelity: high` 부재 — 가장 큰 구조 원인
이미지 편집 API는 마스크가 없으면 **사실상 전체 재생성**이다. 원본을 붙잡는 손잡이가 이 파라미터다.

```jsonc
// multipart/form-data
{ "model": "gpt-image-1", "input_fidelity": "high", ... }   // image=<원본 파일>
```

- 비용: 입력 토큰 가산(정사각 첨부가 가장 쌈). 요청당 체감 +$0.04~0.06 수준
- ⚠ **모델별로 다르다** — 항상 고충실도로 처리하는 모델에 이 파라미터를 보내면 **요청이 실패**한다.
  모델 분기해서 붙였다 뗐다 하게 짜라. 400이 오면 파라미터 없이 1회 재시도하는 폴백도 넣어라.
- ⚠ **목적이 반대면 빼라** — 원본을 *변형*하는 게 목적(스타일 트랜스퍼)이면 high가 방해한다.
  우리 사고의 뿌리가 이거였다: **화풍을 바꾸려고 일부러 fidelity를 뺐던 옛 스크립트를,
  화풍을 지켜야 하는 작업에 그대로 복사**해 왔다.

### L3. ⚠ 시트 격자 — 칸이 정사각에서 멀수록 모델이 요청을 어긴다
한 장에 여러 컷을 담아 잘라 쓰면 요청 수가 크게 준다. 다만 격자를 안 지킨다.

| 요청 격자 | 칸 가로/세로 비 | 모델이 지킨 비율 |
|---|---|---|
| 5열 × 3행 | 0.90 | **25%** |
| 4열 × 4행 | 0.67 | **0%** |
| 2열 × 3행 | **1.00** | **75%** |

→ **칸을 정사각으로 설계해라.** 우리는 1024×1536 시트를 **2열×3행 = 6칸(512×512)** 으로 고정했다.

부수 효과가 더 크다: 5×3이면 칸이 307×341이라 얼굴에 300픽셀뿐이고, 그걸 512로 업스케일하면
**뭉개짐이 한 번 더 얹힌다**. 6칸이면 512 네이티브라 리샘플이 0이다(면적 +178%).

**자르기 전에 격자를 검증해라.** 이음매를 검출해 ⓐ있어야 할 자리에 있는지 ⓑ칸 한가운데엔 없는지
둘 다 보고, 어긋나면 **자르지 말고 격리**한다. 안 하면 어긋난 조각이 폴더에 쌓인다
(우리는 이걸 안 해서 **생성 304컷 중 244컷이 쓸 수 없는 조각**이었다).

### L4. ⚠ 지시 충돌·길이
- 실패본은 `"1번 칸: …"` 15개를 나열해 놓고 마지막에 **"글자·번호를 그리지 마라"** 라고 했다.
  정면 충돌이라 실제로 격자선이 그려져 나온 시트가 있다. → 숫자를 지우고 **"왼쪽 위 칸 = …"** 처럼
  위치로 지목한다.
- 프롬프트에 마크다운 `**`를 쓰지 마라. 이미지 모델에겐 그냥 글자다.
- 길이도 줄여라(우리는 1,100자 → 638자). 지시가 많을수록 개별 지시의 무게가 떨어진다.

## 3. 성공한 프롬프트 (그대로 가져다 써라)

`{who}` = 인물 한 줄 묘사(예: "챙 넓은 검정 갓을 쓴 흑발 남성"), `{슬롯}` = 칸별 지시.

### 표정 시트
```
첨부한 그림을 그대로 복제하되 표정만 다른 얼굴 6컷을 한 장에 담아라.
배치는 가로 2칸 세로 3칸의 균등한 격자다.
여섯 칸 모두 첨부 그림과 같은 사람({who})이고, 머리 모양·옷·장신구·배경·조명이 첨부 그림과 같다.
칸마다 얼굴 크기와 눈높이가 같고 머리가 칸 한가운데 온다. 어깨 위 얼굴 클로즈업이다.
여섯 칸 전부 첨부 그림과 같은 파일에서 잘라낸 것처럼 보여야 한다.
첨부 그림에서 달라지는 것은 눈매·눈썹·입 모양뿐이다. 나머지는 첨부 그림을 그대로 옮긴다.
표정은 첨부 그림 속 인물이 실제로 지을 만한 정도로만 움직인다. 놀람이나 화남도 크게 벌리거나 찡그리지 않는다.
첨부 그림에 없던 표시는 넣지 않는다 — 땀방울, 뺨의 빗금, 효과선, 이모지 같은 기호를 그리지 마라.
왼쪽 위 칸 = {표정1}. 오른쪽 위 칸 = {표정2}. …
글자·숫자·격자선·테두리·워터마크는 그리지 않는다.
```

### 자세·장면 시트
```
첨부한 그림의 사람을 그대로 옮겨서, 자세와 배경만 다른 장면 6컷을 한 장에 담아라.
배치는 가로 2칸 세로 3칸의 균등한 격자다.
여섯 칸 모두 첨부 그림과 같은 사람({who})이고, 얼굴·머리 모양·옷이 첨부 그림과 같다.
각 칸은 무릎 위 또는 전신이며 인물이 칸 한가운데 오고 칸마다 인물 크기가 비슷하다.
여섯 칸 전부 첨부 그림과 같은 파일에서 잘라낸 것처럼 보여야 한다.
달라지는 것은 인물의 자세와 그 뒤 공간뿐이다.
왼쪽 위 칸 = {장면1}. …
글자·숫자·격자선·테두리·워터마크는 그리지 않는다.
```

**문장 하나하나가 하는 일**

| 문장 | 왜 있나 |
|---|---|
| "그대로 복제하되" | 프레이밍을 **그리기 → 복제**로 바꾼다. "그려라"라고 하면 새로 그린다 |
| "같은 파일에서 잘라낸 것처럼" | 스타일 축을 **열거하지 않고** 한 방에 묶는다(L1의 미묘한 함정 회피) |
| "머리 모양·옷·장신구·배경·조명이 같다" | 스타일이 아니라 **원본의 사실 묘사**라 오염이 없다. 소실되기 쉬운 것을 못 박는다 |
| "달라지는 것은 눈매·눈썹·입 모양뿐" | 변경 범위를 **양성 목록**으로 좁힌다(금지 목록보다 강하다) |
| "실제로 지을 만한 정도로만" | "이질감"의 정체 = 만화적 과장. 이 한 줄이 막는다 |
| "없던 표시는 넣지 않는다" | 땀방울·효과선 같은 기호가 원본 화풍을 깬다 |
| "왼쪽 위 칸 =" | 숫자 지목과 "글자 금지"의 충돌 제거 |

### 첨부 이미지 준비 — 이것도 프롬프트만큼 중요
- **얼굴 작업이면 얼굴을 크롭해 첨부해라.** 세로로 긴 전신을 통째로 넣으면 얼굴 화소가 1/6이다
- **크롭으로 원치 않는 소품을 잘라내라.** 우리는 원본에서 손·담배가 얼굴 옆에 있었는데, 안 자르면
  **생성된 컷 전부에 그게 따라붙는다**
- 정사각에 가깝게 + 긴 변 1024 이상. 정사각이면 fidelity 토큰 가산도 가장 적다

## 4. 합격 판정 — 눈 말고 숫자로

같은 크기(256×256)로 맞춰 원본과 비교한다. 파이썬 + PIL만으로 된다.

| 지표 | 재는 법 | 합격선 |
|---|---|---|
| 선 강도 | `ImageFilter.FIND_EDGES` 평균 | 원본 대비 **±25% 이내** |
| 굵은 선 비율 | 위 결과에서 값 > 110인 픽셀 % | **±3%p 이내** |
| 상위 8톤 점유 | 밝기 6bit 양자화 후 최빈 8개 합 % | **±8%p 이내** |
| 평균 채도 | HSV의 S 평균 | ±15% 이내 |
| 색 수 | RGB 6bit 양자화 후 distinct | 급감 = 묘사 밀도 붕괴 |

**선 강도와 굵은 선 비율이 핵심이다** — "애니풍이 됐다"는 체감이 이 둘로 잡힌다.
실패본은 셋 다 대폭 초과했고, 성공본은 −9% / −0.4%p / +10.4%p였다.

사람 눈 체크(컷당 5초): ⓐ원본 옆에 놓고 "같은 작가가 그린 같은 사람"으로 보이나
ⓑ**캐릭터 고정 요소**(눈 색·문양·장신구)가 전부 살아 있나 ⓒ하이라이트가 남아 있나
ⓓ만화 기호 0인가 ⓔ격자 칸 수가 요청과 같은가.

## 5. 돈 안 태우는 순서

1. **파일럿 1시트만.** 우리는 $0.31로 GO/STOP을 갈랐다. 전량은 그 다음이다
2. 파일럿은 **가장 깨지기 쉬운 대상**으로 골라라(원본이 제일 회화적·고밀도인 것).
   그게 통과하면 나머지는 안전하다
3. 파일럿 결과를 **§4 지표로 재고** 나서 전량 GO
4. **멱등하게 짜라** — 이미 있는 산출물은 건너뛰게. 재실행이 공짜여야 마음 놓고 고친다
5. 실패본을 **지우지 말고 대조군으로 남겨라**. 다음에 같은 실수를 했는지 숫자로 잴 수 있다
