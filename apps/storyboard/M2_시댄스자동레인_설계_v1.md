## 1. 레인 전체도 (콘티 하류 분기)

```
콘티 폼(viewer/sb.html) ─ POST /api/sb ─ sb-make.yml
   └ 감독 = 페이블·오퍼스(구독 OAuth) / GPT 5.6(OPENAI_API_KEY)   ← 배선 완료
        └ board.md(텍스트 콘티 · 0크레딧)
             ├─ 촬영 kling    → k-make.yml(프롬프트 번들) → 코드블록 복사 → 클링 웹앱 수동   ← 배선 완료
             └─ 촬영 seedance → ★ sd-make.yml(신설) → 힉스필드 MCP → mp4                    ← 이 문서
```

핵심 원칙 = **콘티는 두 레인의 공통 상류**다. `board.md`를 재생성하지 않고 그대로 입력으로 받는다(재해석 = 콘티 승인의 무효화).

## 2. 신설 파일 4개 (배선 시 만들 것)

| 파일 | 역할 | 계승 정본 |
|---|---|---|
| `.github/workflows/sd-make.yml` | 시댄스 발사 잡(디스패치·커밋·push) | `sb-make.yml` 골격 100% |
| `.github/scripts/sdmake.sh` | 프롬프트 조립 + `claude -p --mcp-config` 실행 + 산출 검수 | `sbmake.sh` 골격 100% |
| `prompts/sd-make.md` | 시댄스 레인 헤드리스 지침(콘티 → MCP 호출 계획 → 발사) | `k-make.md` 계약 문법 |
| `functions/api/sd.js` | 뷰어 → 워크플로 디스패치(화이트리스트 재검증) | `api/sb.js` 바이트 계승 |

**신규 뷰어 탭 0개** — 발사 진입점은 콘티 결과부(작업 내역 행)의 버튼 1개. 새 탭·새 화면 신설 없음(⚠배치 = 그 버튼 1개뿐 = §디자인 3-2 사후 확인 대상).

## 3. 인증 설계 (M2 블로커의 해소안)

### 3-1. 시크릿
```
HIGGSFIELD_MCP_TOKEN   # 힉스필드 웹 → MCP 메뉴에서 발급한 토큰(Bearer)
HIGGSFIELD_MCP_URL     # 기본 https://mcp.higgsfield.ai/mcp — 변경 대비 vars로 분리
```
`sb-make.yml`의 `OPENAI_API_KEY` 선례와 동일 등급(레포 Settings → Actions secrets). ⚠️ **키를 넣기만 하면 안 된다** — 현재 레포엔 `higgsfield` 문자열이 0건이라, 아래 3-2의 소비 지점을 만들지 않으면 시크릿은 무효다(260730 실측).

### 3-2. 러너 주입 (커넥터가 안 통하는 영역의 해법)
`claude -p`에 `--mcp-config`를 **파일로** 넘긴다(인라인 JSON은 시크릿이 프로세스 목록·로그에 노출).

```bash
# sdmake.sh 안 — 런타임 생성 · 즉시 chmod 600 · trap으로 삭제
CFG="$(mktemp)"; trap 'rm -f "$CFG"' EXIT; chmod 600 "$CFG"
cat > "$CFG" <<JSON
{ "mcpServers": { "higgsfield": {
    "type": "http",
    "url": "${HIGGSFIELD_MCP_URL:-https://mcp.higgsfield.ai/mcp}",
    "headers": { "Authorization": "Bearer ${HIGGSFIELD_MCP_TOKEN}" } } } }
JSON
claude -p --mcp-config "$CFG" \
  --allowedTools "Read,Glob,Grep,mcp__higgsfield__balance,mcp__higgsfield__models_explore,mcp__higgsfield__generate_video,mcp__higgsfield__job_display,mcp__higgsfield__show_generations" \
  --model "$MODEL" < "$PROMPT"
```

- **허용 도구 화이트리스트가 안전선**이다: `Write/Edit/Bash` 불허(헤드리스 무중단 = kmake 계승) + 힉스필드 쪽도 **읽기·생성 5개만** 허용 → `select_workspace`·`show_plans_and_credits`·결제류 도구는 애초에 호출 불가(오작동 과금 차단).
- 인증 실패 판정 = 첫 `balance` 호출 실패 → `error.log`에 `힉스필드 MCP 인증 실패({http})` + `exit 1`(무성 실패 금지 · sbmake 프리플라이트 패턴).
- 🟡 토큰 만료 주기 = 첫 실패 시점으로 확정(그때 갱신 절차를 이 문서 §3-3으로 증축).

## 4. 3중 크레딧 게이트 (돈이 나가는 유일한 레인)

```
G0 사전   balance → credits < 예상비용 → 발사 자체 중단(error.log · 0원 소모)
G1 견적   generate_video{get_cost:true} → 실제 견적 회신 → sd_out/<id>/cost.json 커밋
G2 승인   뷰어가 cost.json 폴링 → 「N cr ≈ ₩M 결제하고 생성」 버튼 = 운영자 클릭 1회
G3 실발사 generate_video{get_cost 제거} → job_id → job_display 폴링 → mp4 URL
```

- **G2 = 사람 게이트.** 자동 연쇄 금지(운영자 승인 없이 크레딧이 나가는 경로 0). 구현 = 워크플로 2단 분리(`sd-make.yml` = G0·G1까지 / `sd-fire.yml` = G3) 또는 단일 잡 + `environment:` 승인. **권장 = 2단 분리**(승인 대기 중 러너 점유 0 = 25분 타임아웃 소모 없음).
- `use_unlim` = **항상 미전달**(무료 트라이얼 소진 방지 · MCP 스펙상 명시 요청 시에만).
- G1 견적과 260714 원화 추정표가 어긋나면 **견적이 정본** — 뷰어 폼의 사전 표기는 어디까지나 보수 추정(그 문구 이미 존치).

## 5. 클링을 MCP로 안 돌리는 이유 (설계 결정 · 명문화)

`kling3_0`이 힉스필드에 있으므로 기술적으로는 자동화가 가능하다. 그래도 **수동 유지**가 정답이다:

| | 구독 수동(현행) | 힉스필드 MCP 경유 |
|---|---|---|
| 한계비용 | **0원**(연 220만 이미 지불) | 크레딧 종량(중복 지출) |
| 품질 통제 | 웹앱 UI 전 기능(모드·업스케일·리드로) | MCP 노출 파라미터로 축소 |
| 자동화 | 불가(복붙) | 가능 |

→ 결론: **자동화 가치 < 중복 지출 + 기능 축소.** 프롬프팅 레인은 존치하고, MCP 클링은 "구독 한도 소진 시 비상 우회로"로만 문서에 남긴다(기본 비노출).

## 6. 산출 계약

```
viewer/sd_out/<id>/
  ├ plan.md      G1 단계 = 호출 계획(모델·초·비율·해상도·참조·프롬프트 전문) — 사람이 읽고 승인
  ├ cost.json    { "credits": 68, "won": 3143, "model": "seedance_2_0", "duration": 15, "at": "<KST>" }
  ├ job.json     G3 = { "job_id": "...", "status": "queued|completed|failed" }
  ├ video.url    완료 시 mp4 URL 1줄(바이너리는 레포에 안 넣는다 = 용량 폭발 방지)
  └ error.log    실패 사유 1줄(무성 실패 금지)
```
- **mp4는 커밋하지 않는다.** 뷰어는 `video.url`을 `<video src>`로 재생(edit 미리보기 부품 계승). 영구 보관이 필요하면 R2 이관을 별건으로.
- id 규칙 = `YYMMDDHHMMSS-<6hex>` KST(`api/sb.js`·`k.js` 동일 계약).

## 7. 폼 축 → 시댄스 파라미터 매핑 (통합 폼 확정 후 확정)

| 통합 폼 축 | 시댄스 파라미터 | 비고 |
|---|---|---|
| 비율 | `aspect_ratio` | 9:16·16:9 · 그 외는 `width`/`height` 파생 |
| 길이 | `duration` | ✅ ≤30s 단일 생성 = 분막 불필요(30s 초과만 클립 분할) |
| 화질 | 해상도 파라미터 | 🟡 `models_explore`로 지원값 확정 후 확정(≤4K) |
| 표현1·2·세부 | 프롬프트 본문 | 화풍 어휘 = `k-make.md` 유파 앵커 사전 그대로(드리프트 0) |
| 네거티브 | 프롬프트 회피 서술 | 전용 필드 미확인 → 본문 흡수 + 📌 고지 |
| 오디오 | `generate_audio`/`sound` | ✅ 모델이 선언할 때만 전달 · 시댄스 오디오 참조는 `medias` role=audio |
| 레퍼런스 | `medias[].value` | ⚠️ URL 직전달 불가 = `media_import_url` → `media_id` 경유(허용 도구에 추가 필요) |

## 8. 작업 순서 (배선 착수 시)

1. **G0 확인** — `balance`로 유료 플랜·크레딧 실측(커넥터 계정 = 유료 계정인지). 불일치면 커넥터 재연결이 선행.
2. `models_explore(seedance_2_0)` 1회 → 해상도·프레임·오디오 지원값을 §7 🟡 칸에 확정 기입.
3. `prompts/sd-make.md` 작성 → `sdmake.sh` → `sd-make.yml` → `api/sd.js` 순(상류부터 = 각 단계 단독 테스트 가능).
4. **최소 비용 실증 1회** = 4s·480p(≈6cr)로 G0~G3 전 구간 관통 → 실측을 `CASES.md`에 적립하고 이 문서 🟡 태그 승격.
5. 통합 폼(플레이그라운드 프리셋 확정분) 배선은 **그 다음** — 레인이 도는 걸 본 뒤 UI를 붙인다(역순 = 폼만 있고 발사가 죽는 상태).

## 9. 실패 모드와 방어

| 실패 | 증상 | 방어 |
|---|---|---|
| 커넥터 계정 ≠ 유료 계정 | 잔액 10cr에서 생성 거부 | G0가 발사 전 차단 · error.log에 계정 힌트 |
| 토큰 만료 | 첫 `balance` 401 | 명시 실패 + 갱신 안내(§3-2) |
| 잡 장기 미완 | `job_display` queued 고착 | 폴링 상한 = 경량 10분/헤비 20분(`imgedit` 판례 계승) · 초과 = error.log |
| 견적↔실과금 괴리 | 예상보다 더 나감 | `transactions` 사후 대조를 실증 1회에 포함(🟡) |
| 동시 발사 중복 과금 | 같은 id 2회 | `concurrency: sd-make-<id>` + `cancel-in-progress:false`(sb 계승) |
| 크레딧 소진 | 생성 실패 | 자동 충전·결제 도구는 **화이트리스트에서 제외** = 세션이 임의 결제 불가 |
